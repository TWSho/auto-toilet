# トイレ自動化 Web UI 仕様書

## 1. 概要

マイコンで制御しているトイレの自動化システムに対し、Webブラウザ経由で操作するための制御パネルUIを作成する。
本仕様書はUI（画面構成・操作方法・表示内容）を対象とし、現時点の実装（React製フロントエンド、`src/`以下）に基づいて記載する。
フロントエンドはM5StampS3が提供するHTTP API（詳細は`WebUIバックエンド仕様.md`）と通信し、実機の状態取得・操作を行う。状態表示は`GET /api/status`のポーリング（推奨1000ms間隔）で更新し、各操作は対応するAPIエンドポイントを呼び出して実行する（カードごとのエンドポイント対応表は7章）。乾燥・フタ自動開閉は引き続き未実装（詳細は6章）。

## 2. 前提・利用シーン

- 想定デバイス：トイレ内に横向き（ランドスケープ）で設置するパネル・タブレット
- 操作環境：タッチ操作が中心。ボタン等のタップ領域は大きめに確保する
- 利用者：家族など限定された人数（認証・権限管理は対象外）
- 画面サイズ：横長画面を主軸とし、幅を活かしたレイアウトとする（縦スクロール前提の縦長UIにはしない）。900px以下では1カラム縦積みにフォールバックする

## 3. 画面構成

タブ切り替えは行わず、横長の画面幅を活かして3つのカード（トイレ／LED・BGM／シーン）を左右に並べたカラムレイアウトとし、全カテゴリに常時アクセスできる状態にする。ヘッダーや共通ステータスバーは設けず、各カードがそれぞれ独立して画面高さいっぱいに配置される。

```
┌───────────────┬──────────────┬─────────────┐
│                │              │             │
│    トイレ       │  LED（上段）  │   シーン      │
│                │  ─────────   │             │
│  [流す(大/小/ECO)]│  BGM（下段） │ [ シーン1 ]  │
│  [止][おしり][やわらか][ビデ]│  │ [ シーン2 ]  │
│  水勢 ●●●○○ 弱/強 │              │ [ シーン3 ]  │
│  洗浄位置 前/後  │              │             │
│  便座温度 低中高  │              │             │
│  温水温度 低中高  │              │             │
│                │              │             │
│  [ 詳細 ▾ ]     │ [詳細▾][詳細▾]│  [ 詳細 ▾ ]  │
└───────────────┴──────────────┴─────────────┘
   1.6fr             1.05fr          1fr
```

補足：
- グリッド比率は「トイレ 1.6fr : LED・BGM 1.05fr : シーン 1fr」（`src/index.css` `.columns`）
- LEDとBGMは別カラムではなく、1枚のカード内に上下2モジュールとして同居する（`LedBgmCard.tsx`）
- 各カードは「主要操作（常時・上部に大きく表示）」と「詳細操作（詳細ボタンの中）」の2階層。詳細ボタンはカード内でアコーディオン展開する（`DetailToggle.tsx`）
- 画面全体は縦スクロールさせない設計（900px超の横長時）。900px以下では1カラムに折り返し、縦スクロールを許容する
- 3カードとは別に、人感センサー調整用の設定パネルをモーダルとして追加する。画面右下に固定表示する歯車アイコンから開閉する（4.5節）
- 通信状態インジケータを画面右上に固定の小バッジとして常時表示する（5章参照）。全幅ヘッダーは設けないため、既存のカードレイアウトの外側に最小限のオーバーレイとして配置する
- 全幅ヘッダーおよび緊急停止ボタンは**未実装**（6章参照）

## 4. 各機能のUI仕様

### 4.1 トイレ制御（`ToiletCard.tsx`）

| 表示 | 要素 | 内容 |
|---|---|---|
| 主要 | 在室状態 | `roomState`（`GET /api/status`）に応じて「不在」「入室中」「滞在中」をカード上部に表示 |
| 主要 | 流す | 「流す(大)」「流す(小)」「流す(ECO)」の3チップをカード最上部に横並び表示。タップで約0.9秒アクティブ表示（フラッシュ演出） |
| 主要 | 洗浄スプレー | 「止」「おしり」「やわらか」「ビデ」の4ボタン。おしり/やわらか/ビデはトグル式（同じものを押すと解除、別のものを押すと切り替え）、「止」は常にactiveSprayをクリア |
| 主要 | 水勢 | 1〜5の5段階をドット表示。「弱」「強」ボタンで増減 |
| 主要 | 洗浄位置 | 「前」「後」ボタンで前後に段階移動（1〜5段階、内部値のみでドット表示なし） |
| 主要 | 便座温度 | 3段階（低/中/高）をドット表示＋サイクルボタン（タップで低→中→高→低と循環） |
| 主要 | 温水温度 | 便座温度と同様の3段階サイクル |
| 詳細 | パワー脱臭 | ON/OFFトグル（入/切ピル） |
| 詳細 | ノズルそうじ | 瞬間動作ボタン（`nozzle_clean`はmomentaryコマンドのため、ON/OFFではなく単発実行） |
| 詳細 | オート洗浄 | ON/OFFトグル（入/切ピル） |

**実装状況とクールダウンのフィードバック（本カードの全ボタン共通）**：本カードの操作はすべて`POST /api/toilet/commands/{id}/execute`を呼び出すIR送信である。
- `GET /api/toilet/commands`で`implemented:false`となっているコマンドはボタンをグレーアウトし操作不可にする。押下時に`501`が返った場合も同様に「未対応」であることをトースト等で通知する（現状「流す(大)」以外の大半の詳細操作が該当。6章参照）
- 実行APIが`409`（クールダウン中、`{"error":{"code":"cooldown"}}`）を返した場合、対象ボタンを一時的に無効化するか「少し待ってから操作してください」を表示する（最小間隔はコマンド種別により150ms〜2000ms、`WebUIバックエンド仕様.md`参照）

未実装：乾燥、フタ自動開閉（6章参照）

### 4.2 LED制御（`LedBgmCard.tsx` 上段モジュール）

| 表示 | 要素 | 内容 |
|---|---|---|
| 主要 | 明るさ | 横長バー全体がスライダーになっており、現在の色で塗りつぶし表示。「点灯中/消灯」＋%表示を重ねる（明るさ0%を消灯として扱う。独立したON/OFFトグルはない） |
| 主要 | よく使う色 | プリセット4色（電球色／昼白色／常夜灯／ピンク）のスウォッチをワンタップ選択。選択中は枠でハイライト |
| 詳細 | カスタムカラー | ネイティブのカラーピッカー（`<input type="color">`）で自由指定。選択した色は`PUT /api/led`経由でWLED実機へそのまま反映される |

### 4.3 BGM制御（`LedBgmCard.tsx` 下段モジュール）

| 表示 | 要素 | 内容 |
|---|---|---|
| 主要 | 現在再生中表示 | 曲名・アーティスト名をアイコン（プレースホルダー）付きで表示 |
| 主要 | 再生/一時停止 | 大きめのトグルボタン（アイコン＋ラベル切り替え） |
| 主要 | 音量 | スライダーで0〜100%調整 |
| 詳細 | 曲送り/戻し | ◀◀ / ▶▶ ボタン |
| 詳細 | リピート/シャッフル | トグルアイコン（オン時ハイライト） |
| 詳細 | シークバー | 再生位置スライダー（`mm:ss / 3:10`表示。`elapsedSec`/`durationSec`は`GET /api/bgm`から取得する実データだが、モジュールに再生位置取得APIがないためバックエンド側で`millis()`差分から算出した概算値であり、厳密な同期はできない） |
| 詳細 | 選曲 | 曲一覧（`SONGS`定数、5曲）をリスト表示。タップで即選曲＋自動再生開始、現在再生中の曲をハイライト |

### 4.4 シーン（`SceneCard.tsx`）

LEDとBGMを組み合わせた設定をワンタップで呼び出す機能。

| 表示 | 要素 | 内容 |
|---|---|---|
| 主要 | シーン一覧・実行 | `GET /api/scenes`で取得した`primary: true`のシーン（リラックス／集中／パーティ）をカード形式で常時表示。タップで`POST /api/scenes/{id}/execute`を呼び出し即時反映（LED色・明るさ・BGM選曲・再生開始を一括変更）。シーンAPIに説明文フィールドは無いため、サブテキストは明るさ％と曲名から組み立てて表示する |
| 詳細 | その他のシーン | `primary: false`のシーン（おやすみ／来客）を詳細内に一覧表示。タップで同様に`POST /api/scenes/{id}/execute`を呼び出す |
| 詳細 | 新規シーン作成 | シーン名・色（カラーピッカー）・明るさ（スライダー）・曲（セレクトボックス）を指定して「保存」ボタンで一覧に追加（`POST /api/scenes`）。バックエンド側のLittleFS（`/scenes.json`）に永続化され、リロード・再起動後も保持される |

未実装：シーンの編集・削除

### 4.5 設定パネル（人感センサー、新規）

3カード（トイレ／LED・BGM／シーン）とは別に、人感センサー（LD2410）のパラメータを調整するモーダルパネルを追加する。画面右下に固定表示する歯車アイコンから開閉する。他カードと異なり、変更内容は明示的な保存操作をするまでNVSに確定保存されない点が特徴。

| 表示 | 要素 | 内容 |
|---|---|---|
| 主要 | 感度（sensitivity） | 0〜100、刻み10のスライダー |
| 主要 | 検知距離（maxGate） | 1〜8、刻み1のスライダー（1ゲート＝0.75m） |
| 主要 | 滞在継続時間（stayDurationSec） | 5〜60秒、刻み5のスライダー |
| 主要 | 未保存インジケータ | `dirty: true`の間「未保存の変更があります」を表示し、保存ボタンを強調表示する |
| 主要 | 保存 | ボタン押下で`POST /api/settings/save`（ボディなし）を呼び、現在のライブ値をNVSへ確定保存する |

- 取得：パネルを開いた際に`GET /api/settings`（`{ current, saved, dirty }`）で現在値を取得する
- ライブ変更：スライダー操作のたびに`PUT /api/settings`（変更したいフィールドのみ送信）を呼び、即座にセンサーへ反映する（この時点ではNVS未保存）
- 挙動の違い：他カードは操作＝即時かつ確定（機器側にそのまま残る）だが、本パネルはライブ反映と確定保存が分離している。「保存」を押さずにパネルを閉じたり機器が再起動したりすると、直前の`saved`値に戻る点をUI上で明示する

## 5. 共通UI要素

- **主要/詳細の2階層構成**：各カードは`primary-zone`（常時・大きく表示）と`detail-panel`（`DetailToggle`タップで開閉）に分かれる。共通コンポーネント`GlassPanel`/`GlassButton`/`DetailToggle`で統一
- **デザイントーン**：白ベースのフラットなカードデザイン。コンポーネント名には`Glass`が残るが、実際のスタイル（`index.css`）はぼかし（backdrop-filter）を使わないフラット表現。アクセントカラーはモノトーン1色（`--accent: #292929`）で統一し、アイコングリフのみブルー／パープル／レッドの差し色を許容する
- **タップ領域**：`GlassButton`で統一的に確保（角丸・パディング込み）
- **フィードバック**：操作は即座にstate更新され見た目に反映（例：流すチップの一時的アクティブ表示、スライダー位置、スウォッチのハイライト）
- **ステータス表示**：カード横断の共通ヘッダーは無く、各カードが自分の状態のみを表示する（在室状態はトイレカード、通信状態のみ下記の通り例外的に画面共通で表示する）
- **通信状態インジケータ**：画面右上に固定の小バッジを常時表示する。`GET /api/status`のポーリングが一定回数（目安3回）連続で失敗した場合、「マイコンと通信できません」等のオフライン表示に切り替える。個別の`wifi.connected`／`mqtt.connected`／`wled.reachable`は設定パネル内などで詳細表示する
- **トースト通知**：未対応コマンド（`501`）、クールダウン中（`409`）、WLED未応答（`502`）など操作が実行できなかった場合に、画面下部などへ一時的なメッセージを表示する共通コンポーネントを追加する

## 6. 現状の制約・未実装事項

以下は仕様上の想定はあるが未実装、または当面の仕様外である：

- **トイレ詳細操作の多くが未対応**：IRコードは「流す(大)」相当のみ収録済みで、それ以外（流す(小/ECO)、洗浄スプレー各種、水勢、洗浄位置、便座/温水温度、脱臭、ノズルそうじ、オート洗浄）は`GET /api/toilet/commands`上`implemented:false`となり、ボタンはグレーアウト・操作不可の状態が続く。IRコード収録が完了次第、コード変更なしに順次有効化される
- **トイレの追跡状態はソフトウェア側の推定値**：IRは一方向送信のため実機から状態を読み出せない。水勢・洗浄位置・温度等の表示値はバックエンドが送信履歴から推定・保持している値であり、物理リモコンでの直接操作や機器の電源断があった場合は実機とズレる可能性がある
- **全幅ヘッダー／ステータスサマリー**：未実装（通信状態インジケータのみ小バッジとして例外的に追加。5章参照）
- **緊急停止ボタン**：未実装
- **ダークモード**：未実装（ライトテーマのみ、CSS変数もダーク定義なし）
- **トイレ**：乾燥、フタ自動開閉は未実装
- **LED**：独立したON/OFFトグルは未実装（明るさ0%を消灯として扱う）
- **シーン**：編集・削除は未実装（新規作成の追加のみ対応）
